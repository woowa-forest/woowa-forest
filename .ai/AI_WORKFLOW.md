# AI 협업 워크플로우

> Claude Code와 함께 해커톤에서 빠르게 개발하는 방법

---

## 권장 워크플로우

```
[기획] → [타입 정의] → [목업 UI] → [기능 연결] → [스타일 다듬기]
  5분       10분          15분          20분            10분
```

### Phase 1: 기획 (5분)

AI와 함께 기능 스펙 정리:
```
내가 만들 기능은 [기능명]이야.
사용자가 [행동]을 하면 [결과]가 되는 기능이야.
필요한 화면과 컴포넌트를 목록으로 정리해줘.
```

### Phase 2: 타입 정의 (10분)

인터페이스 먼저 확정 → `shared/types/`에 추가:
```
[기능명]에 필요한 TypeScript 타입과 인터페이스를 정의해줘.
도메인 객체, API 응답, 컴포넌트 Props 포함해서.
```

### Phase 3: 목업 UI (15분)

먼저 보여지는 화면부터:
```
[화면 설명] 화면을 목업으로 빠르게 만들어줘.
실제 데이터 연결 없이, 하드코딩 데이터로.
동작하는 것처럼 보이면 됨.
```

### Phase 4: 기능 연결 (20분)

상태 관리 + API 연동:
```
[목업 컴포넌트]에 실제 기능을 연결해줘.
상태: [필요한 상태]
API: [연동할 엔드포인트 또는 목업 함수]
```

### Phase 5: 스타일 다듬기 (10분)

마지막에 한 번에:
```
전체적으로 스타일을 다듬어줘.
일관성, 간격, 컬러 톤 맞춰서.
```

## Claude Code 단축키 및 팁

### 파일 컨텍스트 활용

Claude Code는 현재 열린 파일을 자동으로 인식합니다.
관련 파일을 열어두고 질문하면 더 정확한 답변을 받을 수 있습니다.

```
# 여러 파일 동시에 컨텍스트로 주기
@파일명1 @파일명2 이 두 파일을 참고해서 [요청]해줘
```

### 효과적인 반복 개선

1. 초안 생성 → 2. 동작 확인 → 3. 구체적인 피드백 → 4. 수정
```
# 피드백 방식
"이 부분만 수정해줘: [구체적인 위치와 원하는 변경사항]"
"[이 기능]은 유지하고, [저 부분]만 바꿔줘"
```

### 막혔을 때

```
이 코드가 [증상]인데 이유를 설명해줘. (수정 말고 설명만)
```
→ 이해 후 수정 요청 (바로 수정 요청보다 이해가 먼저)

## 시간 관리 전략

### "일단 동작" 우선주의

해커톤에서는 완벽한 코드보다 동작하는 코드가 우선:

```
# 빠른 구현 요청
"완벽하지 않아도 되니까 일단 동작하는 버전으로 만들어줘.
 하드코딩, 목업 데이터 써도 됨."

# 나중에 개선
"이전에 만든 [기능]을 실제 데이터 연결로 개선해줘."
```

### 막힌 시간 15분 룰

15분 이상 같은 문제에 막혔다면:
1. 에러 메시지 + 코드 전체를 AI에 붙여넣기
2. AI도 해결 못하면 → 팀원에게 공유
3. 우회책 찾기 (다른 방식으로 같은 결과)

## AI가 자주 틀리는 것들

| 상황 | 증상 | 대응 |
|------|------|------|
| 오래된 API 사용 | 동작 안 하는 코드 | 버전 명시: "React 18, Next.js 14" |
| 과도한 추상화 | 너무 복잡한 코드 | "심플하게, 최대 50줄로" |
| 가정한 파일 구조 | import 에러 | 실제 파일 경로 알려주기 |
| 타입 any 남용 | 타입 에러 | "any 쓰지 말고 정확한 타입으로" |

## 생산성 부스터

### 컴포넌트 빠른 스캐폴딩

```
[컴포넌트명] 컴포넌트의 기본 구조(껍데기)만 빠르게 만들어줘.
Props 타입, useState, useEffect 자리만. 로직은 내가 채울게.
```

### 스타일 클론

```
이 스타일과 비슷하게 만들어줘: [레퍼런스 설명 또는 스크린샷]
Tailwind 클래스로, 색상은 [원하는 색상]으로 바꿔서.
```

### 반복 코드 자동화

```
[패턴] 형태의 코드가 [N]개 필요해.
[예시 하나] 이런 식으로, 나머지도 만들어줘.
데이터만 다르고 구조는 동일해.
```
